# esp32-dct3 — Nokia 3310 на ESP32-S3

Порт `nokia-dct3-emulator` (DCT3/MAD2, реальная прошивка) на ESP32-S3:
экран SSD1306 128×64 по I2C, клавиатура через UART-консоль.
Прошивка телефона не входит в репозиторий — нужен свой `.fls` (3310, 2 МБ).
Имя оператора виртуальной SIM-карты: `esp32-s3`.

Код проекта распространяется по лицензии MIT. Встроенная копия ARM-ядра mGBA
в `components/dct3/mgba-arm` сохраняет лицензию MPL-2.0. Образы прошивок Nokia
не входят в проект и не должны добавляться в репозиторий.

## Железо

| Сигнал | По умолчанию |
|---|---|
| SSD1306 SDA | GPIO8 |
| SSD1306 SCL | GPIO9 |
| PC Speaker / пассивный зуммер (PWM) | GPIO5 |
| SSD1306 адрес | 0x3C |
| I2C | 400 кГц, порт 0 |
| UART-клавиатура | UART0 (console), 115200 |

Пины и адрес меняются в `idf.py menuconfig` → *DCT3 emulator*.
PC Speaker получает PWM с частотой зуммера телефона или основного тона клавиатуры.
`CONFIG_DCT3_SPEAKER_GPIO=5`; значение `-1` отключает звук.
Магнитный низкоомный PC Speaker подключается через транзисторный драйвер с общей
землёй ESP32; напрямую к GPIO его подключать нельзя. Для проверки отправьте `b`
через COM-порт: три ноты 660, 880 и 1320 Гц независимо от звука прошивки телефона.
В панели `tools/keypad_gui.py` та же проверка запускается кнопкой «Звук».
Нужен модуль с PSRAM (минимум ~4 МиБ свободной) и flash ≥ 8 МБ.
Если PSRAM octal (WROOM-2 / N16R8V), включите `CONFIG_SPIRAM_MODE_OCT=y`
и выключите `CONFIG_SPIRAM_MODE_QUAD`.

## Сборка

```sh
idf.py set-target esp32s3
idf.py menuconfig      # проверить PSRAM и пины
idf.py build
```

Проект использует новый драйвер I2C (`driver/i2c_master.h`), нужен ESP-IDF 5.2+.

## Прошивка

```sh
# 1. приложение
idf.py -p COMx flash

# 2. образ телефона — сырым блоком в партицию "fw" (offset 0x1A0000)
esptool.py --chip esp32s3 -p COMx -b 921600 \
    write_flash 0x1A0000 путь\к\3310.fls
```

Если `.fls` меньше 2 МБ, допишите его нулями/0xFF до 2 МБ либо поправьте
`fw_size` в `emu_harness.c` (сейчас читается ровно `model->mem.flash_size`).

Монитор:

```sh
idf.py -p COMx monitor
```

## Клавиши

| Ввод | Клавиша |
|---|---|
| `0`…`9` | цифры |
| `*`, `#` | `*`, `#` |
| `u` / `d` | вверх / вниз |
| `m` или Enter | Menu (левая софт-клавиша) |
| `c`, Backspace | Names / C (очистка) |
| `p` | Power |

Клавиша удерживается 200 000 инструкций, затем отпускается; следующая
принимается после паузы 1 200 000 инструкций (как в web-харнессе).

## Как это устроено

- `components/dct3` — неизменённое ядро эмулятора + mGBA ARM7TDMI.
  Собрано только под 3310 (`DCT3_MODEL_3310_ONLY`); host-транспорты
  (DSP bridge, SIM bridge, WAP host) выключены через `ESP_PLATFORM`.
- `main/emu_harness.c` — загрузка `.fls` из партиции, `mad2_init`,
  `dct3_boot_at(0x200040)`, пошаговый цикл с `harness_observe` /
  `harness_post_step`, таймерами, FIQ/IRQ и секвенсором клавиш.
- `main/ssd1306.c` — кадр PCD8544 (6 страниц × 84 байта) копируется в
  центр экрана 128×64; отправляются только изменившиеся страницы.
- `main/kbd_serial.c` — UART → KeyId → очередь → матрица клавиш.
- `main/main.c` — две задачи: эмулятор на core 1 и дисплей на core 0;
  пейсинг 13 МГц по `esp_timer`.

## Отличия от upstream

- Плоское адресное пространство — 4 МиБ вместо 16 МиБ: для 3310
  (flash 0x200000…0x400000) этого достаточно, а PSRAM остаётся свободной.
  Меняется одним `DCT3_RAM_SIZE` в `components/dct3/CMakeLists.txt`.
- Зуммер мелодий/игр и основной тон клавиатуры выводятся PWM на GPIO5 (`main/speaker.c`).
  Полный PCM-поток и смешивание двух частот DTMF пока не подключены:
  `mad2.pcm_sink = NULL`.
- Сеть, реальный SIM-мост и WAP-хост выключены.
- EEPROM телефона (192 КиБ) сохраняется в разделе `settings` на flash ESP32.
  Запись выполняется после секунды без новых изменений; переписываются только
  изменившиеся секторы по 4 КиБ. Две копии с CRC защищают последний завершённый
  снимок от прерванной записи. Снимки привязаны к образу прошивки телефона.
  Перед отключением питания дождитесь `settings saved` или нажмите «Сохранить»
  в панели управления. При обновлении проекта не стирайте раздел `settings`.

Регистры ARM и таблица доступа к памяти размещаются во внутренней RAM,
а 4 МиБ памяти телефона — в PSRAM. Неизменившиеся кадры не публикуются повторно.
Отключённый журнал LCD уменьшен с 128 КиБ до 512 байт; аппаратный кэш PSRAM
увеличен до 64 КиБ с линией 64 байта. После старта свободно около 140 КиБ SRAM.
Профилирование горячего цикла выключено по умолчанию; для диагностики можно
включить `CONFIG_DCT3_PROFILE` в `menuconfig`.
Обработчики регистров, таймеров и ROM-6 DSP исполняются из IRAM; ядро собирается с `-O3`.
Интерпретатор выполняет пакеты инструкций без отдельного вызова `ARMRun` на каждую.
После первых 10 секунд времени телефона цикл ожидания байта RAM пропускается до
ближайшего события, не далее 1 мс и границы кадра. Ускорение также останавливается
перед отпусканием клавиш. При ожидающих прерываниях работает обычный интерпретатор.
Это ускоряет ожидание; вычислительные участки
продолжают ограничиваться скоростью интерпретации.
После восстановления настроек RTC-SEC тоже обслуживается быстрым путём таймеров;
просроченные сроки выключенных FIQ8/WDT не блокируют пропуск ожидания.
Команда `v` выводит состояние памяти и принудительно сохраняет завершённые изменения.
На SSD1306 передаётся только изменившийся диапазон байтов каждой страницы.
Звук проверяется после каждого пакета работы эмулятора; короткие сигналы зуммера и клавиатуры
удерживаются не менее 15 мс, чтобы короткий писк был слышен.

## Панель управления с кнопками (Windows)

В `tools/keypad_gui.py` — Tkinter-панель с клавиатурой Nokia 3310: выбор
COM-порта, журнал консоли и кнопки. Она отправляет те же символы, что и
терминал: `0-9 * #`, `u`/`d`, `m`, `c`, `p`.

```powershell
python tools\keypad_gui.py
```

Или двойным щелчком по `tools\keypad_gui.bat`. Выберите порт платы и нажмите
«Подключить». Горячие клавиши: цифры, стрелки, Enter = Menu, Backspace = C,
`P` = PWR. Кнопка `Reset` дёргает RTS (на типовой схеме CH340 это EN); если
RTS не подключён, используйте кнопку EN на плате.

Требования: Python 3 с `tkinter` и `pyserial`.
